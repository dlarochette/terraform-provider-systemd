# ACC over SSH Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the same `TestAcc*` suite over `remote.Dial` (SSH/SFTP) via `make testacc-ssh` and a hard-fail CI job; keep nspawn ACC unchanged.

**Architecture:** `accClient` selects SSH when `SYSTEMD_ACC_SSH_HOST` is set; harness `acc-nspawn-ssh.sh` prepares guest `sshd` on port 2222 with an ephemeral key. Add `Host.Exec` so ACC helpers work on both transports.

**Tech Stack:** Go, golang.org/x/crypto/ssh, systemd-nspawn, OpenSSH, GitHub Actions.

## Global Constraints

- Spec: `docs/superpowers/specs/2026-07-30-acc-ssh-design.md`
- Tags without `v` prefix; target release **0.10.0**
- Conventional Commits in English
- Shared-network guest; sshd on **2222**, Dial `127.0.0.1:2222`
- No bastion / password auth in ACC
